# Розклад приміських поїздів

Персональний застосунок, що показує розклад електропоїздів для твоїх
станцій (Вересоч, Носівка, Тарасівка, Ніжин, Київ-Волинський,
Київ-Пасажирський — останні дві лише в напрямках Ніжин/Фастів),
замість ручного пошуку на swrailway.gov.ua щоразу.

## Як це працює

1. `scripts/fetch_and_build.py` завантажує сторінки розкладу з
   swrailway.gov.ua для кожної станції з `scripts/stations.json`,
   парсить таблицю рейсів і зберігає результат у `data/schedule.json`.
2. `index.html` — сторінка, яка читає `data/schedule.json` і показує
   акуратний список найближчих рейсів, з підсвіченим найближчим
   потягом.
3. GitHub Actions (`.github/workflows/update-schedule.yml`) щодня
   вранці сам запускає скрипт і оновлює дані в репозиторії.

Скрипт запускається на GitHub-серверах (твій репозиторій), а не в
Claude — оскільки мій сервіс не має доступу до swrailway.gov.ua.

## Встановлення (один раз)

1. Створи новий приватний або публічний репозиторій на GitHub і
   заливай туди весь цей каталог (`uz-schedule/`) як корінь
   репозиторію.
2. Settings → Pages → Source: постав "Deploy from a branch",
   branch `main`, папка `/ (root)`. Збережи — за хвилину-дві
   з'явиться посилання виду `https://<твій-логін>.github.io/<репо>/`.
3. Settings → Actions → General → Workflow permissions: постав
   "Read and write permissions" (потрібно, щоб Action міг
   закомітити оновлений `schedule.json`).
4. Перейди в вкладку Actions → "Update train schedule" → Run workflow,
   щоб одразу отримати перші реальні дані (далі він бігтиме сам щодня
   о 04:00 за Києвом).

## Як визначається напрямок (по відрізках, а не по лінії загалом)

Кожна станція має список конкретних "відрізків" до інших відстежуваних
станцій (`segments` у `stations.json`). Рейс потрапляє у відрізок,
якщо той самий `tid` (унікальний ідентифікатор потяга) також є в
даних станції-пари — тобто це буквально той самий фізичний потяг,
що зупиняється на обох. Напрямок (туди/назад) визначається
порівнянням часу: на якій із двох станцій потяг раніше — звідти він
і їде.

Це набагато точніше, ніж проксі через сусідню станцію: рейс Київ↔Ніжин,
що не зупиняється на Вересочі чи Носівці, раніше губився, а тепер
зіставляється напряму.

## Якщо захочеш додати чи прибрати станцію або відрізок

Онови `scripts/stations.json` — додай об'єкт із `name`, `param`
(`sid` або `geo`), `id` (число з URL станції), `segments` (список пар
"інша станція + підписи туди/назад") і `label_order` — порядок, у
якому групи показуються на сторінці. Кілька відрізків можуть свідомо
використовувати однакові підписи (наприклад, на Носівці підтвердження
"їде до Києва" приходить і від Київ-Пасажирського, і від
Київ-Волинського — обидва підпадають під один напис "На Київ").
Для великих вузлових станцій постав `drop_unmatched: true`, щоб
рейси, які не належать жодному з твоїх відрізків, просто не
показувались, а не захаращували "Інше".

## Поточний стан цього прев'ю

У `data/schedule.json` зараз лежать реальні дані тільки для
Київ-Пасажирського (з прикладу сторінки, яку ти надіслав) — щоб можна
було одразу побачити, як виглядає інтерфейс. Решта станцій
заповняться реальними рейсами після першого запуску Action.
